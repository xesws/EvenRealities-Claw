# 截图

全部来自本机跑起来的真实链路（网关 + 插件 + agent 三个进程），不是设计稿。
左边那块黑底绿字的是**眼镜 HUD**（G2 每只眼 576×288、4 位灰阶、行高固定 27px），
右边是**手机上的插件本体**（按住说话 / 打断 / 清屏），中间那排是浏览器夹具的故障注入开关。

| 文件 | 内容 |
|---|---|
| `01-harness-overview.jpg` | 全景。接的是自研 agent（DeepSeek），状态条徽记是干净的「答」 |
| `02-hud-page1.png` | HUD 特写 · 第 1 页。8 行排满，页脚 `1/2 ›` |
| `03-hud-page2.png` | HUD 特写 · 第 2 页。续页首行的 `…` 是跨页锚点，页脚 `‹ 2/2` |
| `04-pairing.jpg` | 配对屏。6 位配对码由服务器生成，10 分钟有效、一次性 |
| `05-w6-fixture-badge.png` | **W6 溯源**：接测试替身时徽记变成「工?」——屏幕自己告状 |
| `06-w6-overview.jpg` | 同上的全景，与 `01` 对照着看：同一块屏，对端不同，徽记不同 |

`02`/`03`/`05` 里的正文是通过 **MCP 控制面**写上去的（外部工具驱动这副眼镜），
写屏要先拿帧租约；用户一开口说话，租约被无条件抢占。

> `01` 与 `06` 的对照就是「演示里没有替身」这条约束的可视化：徽记不是装饰，
> 它由握手时记录的对端身份决定，而且每帧现算。用夹具跑的端到端测试断言
> 每一条状态条都带「?」，用真 DeepSeek 跑的断言一条都不带。
