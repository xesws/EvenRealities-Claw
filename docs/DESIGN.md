# OpenClaw 小龙虾 × Even Realities 眼镜 — 系统设计方案 v1

> 2026-06-11 产出。依据：深度调研（22 条事实经 3 票对抗验证）+ 三方案设计评审（极简瞥视/操作台/对话流，3 评委交叉打分，「一瞥 HUD」全票胜出）+ 架构红队（14 项攻击）。
> 目标：眼镜说话 → 私有服务器上的 OpenClaw 多 Agent（工部/格物/都察）+ Hermes → 眼镜 HUD 实时状态与回复。
> 注：本文为公开脱敏版，内部端口、路径与凭证细节已移除。

---

## 0. 一页结论

**可行，且有官方支持的路径。** 两条路：

| | 主路径：G2 + Even Hub 插件 | 备份路径：G1 BLE 直连 |
|---|---|---|
| 性质 | **官方支持**（Even Hub 开发者平台，2026-04 上线） | 官方公开的 demo 级 BLE 协议（BSD-2-Clause），社区已验证 |
| 形态 | JS/TS web 插件跑在官方手机 App 的 WebView 里，手机是必经中继 | 任意 host（手机/树莓派/Linux）直连双 BLE 链路 |
| mic | `audioControl(true)` → 16kHz PCM 流（10ms 帧） | `0x0E` 开启 + `0xF1` LC3 流，**单次 30s 上限** |
| 显示 | 576×288 画布，16 级绿色灰阶，≤8 文本 container | 640×200 纯单色绿，整屏文本推送（0x4E），每屏 5 行 |
| 中文 | 官方支持（SDK 文档即中文） | 支持（host 端折行，约 23 汉字/行） |

**选定 G2 主路径**（官方 SDK、灰阶层级、4 mic 阵列），G1 路径作为战略备份维护（官方 App 一次更新就可能打断主路径，见 R13）。

**红队两处前提修正**（已接受）：
1. "手机插件 = 纯哑终端"不成立 —— 锁屏/后台挂起是平台级不可控故障，插件必须内置最小本地看门狗（断线帧）。产品定位是 **"亮屏突发会话助手"**（按住说话→看完收起），不是常驻助手。
2. 眼镜会话与其他渠道（如 Discord）的会话 **必须隔离**（独立 sessionKey 命名空间），这也是注入小屏输出风格的唯一手段。

**三个硬条件**：① OpenClaw 网关 token 永不出服务器；② ASR 与 agent 负载 CPU 硬隔离（突发型实例会撞积分悬崖）；③ WSS 按"蜂窝网络常态断连"设计（幂等整屏帧 + 单调序号 + 服务器持有全部状态）。

## 1. 调研事实摘要（设计依据，全部经验证）

### 1.1 官方 SDK（G2）
- Even Hub（hub.evenrealities.com）2026-04-03 上线，**只支持 G2**（G1 全站零提及）。
- `@evenrealities/even_hub_sdk`（npm，MIT，v0.0.10 / 2026-04-10）+ evenhub-cli + 模拟器 + 4 个官方模板（minimal / **asr** / image / text-heavy —— asr 模板可直接当起点）。
- 插件 = WebView 里的 web app（Android Chromium / iOS WKWebView），宿主是官方 Flutter App；插件可自由连任意服务器。目前只有 background-layer 插件；dashboard widget、AI skill 在路线图上。
- 画布 576×288/眼，4-bit 16 级绿灰阶，左上原点；每页 1-12 个 container，文本 container ≤8，单 container ≤1000 字（`textContainerUpgrade` 到 2000）。
- 图片 ≤288×144、每页 ≤4 张、**必须串行队列发送**、官方明确不鼓励频繁发图 → UI 以文本为主。
- mic：`audioControl(isOpen)`，前置条件 `createStartUpPageContainer` 成功；PCM 经 `onEvenHubEvent` 的 `audioEvent.audioPcm`（Uint8Array）。硬件 4-mic 阵列、16kHz PCM 单流。
- **无扬声器、无摄像头** → 声音回放走手机；R1 戒指可做输入。

### 1.2 官方公开协议（G1）
- EvenDemoApp（even-realities org，BSD-2-Clause，活跃维护至 2026-06）公开全协议：TouchBar 0xF5、mic 0x0E、LC3 音频 0xF1（seq 0-255，**30s/次上限**）、BMP 0x15/0x16/0x20、整屏文本 0x4E（host 折行：demo 参数宽 488px、字号 21、每屏 5 行）。
- **双 BLE 链路**（每镜腿一条）：先左、收 ack 才发右 → 刷新预算更紧。
- 硬件：640×200 绿色 Micro LED、25° FOV、20Hz、1000nits、BLE 5.2、无 Wi-Fi。
- 第三方直连已被实践证明：Gadgetbridge（无需官方 App 完成配对+双链路管理）、even_glasses（Python）、MentraOS、fahrplan。

### 1.3 物理共识
- **BLE 是带宽瓶颈**：整屏文本刷新安全节奏 ≈ G2 2Hz（短时 3-5Hz）/ G1 1Hz；20Hz 面板不是瓶颈。
- 眼镜是远端哑屏：折行、分页、节流全部在服务器端做。

### 1.4 未决问题（原型第一周必须实测）
1. **后台存活**：Even App 锁屏/切后台时插件的 mic 流和 WSS 能活多久（iOS/Android 分别测）。
2. **mic 仲裁**：插件录音中长按 TouchBar（官方 Even AI）/ Even AI 进行中开 audioControl，4 象限实测。
3. **TouchBar 事件**对插件的暴露程度：拿不到单击/长按则交互全退 R1 + 语音控制词。
4. `audioControl` 连续开 60s/300s 的行为（是否有 G1 式隐藏上限）。
5. 实测真实可达刷新率（依手机机型浮动），帧调度器必须自适应降频而非写死 2Hz。

## 2. 总体架构

### 2.1 拓扑

```
┌─────────┐  BLE(官方桥)  ┌──────────────────────┐   WSS:443(TLS)   ┌─────────────────────────────────────┐
│  G2眼镜  │◀────────────▶│ 手机: Even App        │◀───────────────▶│ 私有云服务器 (ARM)                    │
│ mic/HUD │               │  └ WebView 插件       │  设备绑定短时效   │  ┌────────────────────────────────┐ │
└─────────┘               │     (哑终端+本地看门狗)│  JWT, 方法白名单  │  │ Lens Gateway (新组件, 唯一公网面) │ │
     │ R1戒指              └──────────────────────┘                 │  │  ├ WSS 终端 + 会话/序号/重放      │ │
     └ 翻页/确认/打断                                                │  │  ├ ASR 管线 (faster-whisper)     │ │
                                                                    │  │  ├ Agent 路由器 (前缀文法)        │ │
   [备份路径: G1 ◀─BLE双链路─▶ 树莓派/常电安卓 ◀─WSS─▶ 同一 Lens GW]   │  │  ├ HUD 帧编排器 (折行/分页/节流)  │ │
                                                                    │  │  └ 告警管道 (去重/限流/熔断)      │ │
                                                                    │  └───────┬────────────────────────┘ │
                                                                    │   loopback│token (永不出服务器)       │
                                                                    │  ┌───────▼────────────────────────┐ │
                                                                    │  │ OpenClaw 网关 (loopback only)    │ │
                                                                    │  │  工部 · 格物 · 都察               │ │
                                                                    │  │ Hermes (Python, whisper/edge-tts)│ │
                                                                    │  └────────────────────────────────┘ │
                                                                    └─────────────────────────────────────┘
```

### 2.2 组件职责

**手机插件（TS，基于官方 asr 模板）— 刻意做薄：**
- `createStartUpPageContainer` 建 4 个文本 container（status / body_stable / body_active / foot）；
- `audioControl` 开关 mic，PCM 二进制帧原样转发 WSS；
- 收服务器下发的"HUD 帧"（已排版），按 container 写入；丢任何中间帧无害（幂等整屏帧）；
- **本地看门狗**：WS 心跳 20s，超时 2 次 → 用本地模板向眼镜推一帧「⛓ 连接丢失」（消灭"旧帧撒谎"的唯一位置）；
- 持有 refresh token（不持有任何 OpenClaw 凭证）。

**Lens Gateway（新服务）：**
- 对外：WSS 服务（443 反代 + TLS + 限速 + fail2ban），API 只有三个动作：提交语音 / 收 HUD 帧 / abort。**绝不透传 OpenClaw 原始 RPC**。
- 对内：loopback 调 OpenClaw 网关（`chat.send` / `agent` 事件流 / `chat.abort`），token 留在服务器。
- 设备配对：发行设备绑定短时效 JWT（15min）+ refresh token，单设备可吊销。

### 2.3 会话语义（R7）
- `sessionKey = lens:<agent>:<deviceId>`，每个 agent 一条眼镜专属会话；空闲 30 分钟开新轮次。
- lens 会话注入专属 system 附加段：**「输出面向 240 字小屏：禁 markdown、先结论后细节、单句短、不用表格」**。
- 跨通道续聊是显式动作：说「接上 Discord 话题」→ 网关把该会话摘要后注入 lens 会话（不共享原始上下文）。
- 同一 sessionKey 内 run 串行化；占用中来新请求 → HUD 提示「上一条还在跑，说打断或稍等」。
- abort 竞态（R14）：以 runId 为键，abort 即标记僵尸丢弃其后续事件；新 run 等 abort 回执或 800ms 超时。

### 2.4 安全模型（R8，CRITICAL）
1. **OpenClaw token 永不出服务器**（它等于服务器 shell；长期有效 token 建议定期轮换）。
2. Lens Gateway 是唯一公网入口；方法白名单；速率限制。
3. 插件端只存 refresh token（泄漏 = 单设备吊销，而非全权失守）。
4. 隐私（R12）：严格按住说话、无 always-on 唤醒词；服务器不落盘原始 PCM，转写即丢；聆听态必须有显著 ●REC 指示，mic 关闭以网关回执确认。

## 3. Lens Gateway 内部设计

### 3.1 ASR 管线（R4/R5 修正后）
- **faster-whisper small/int8**，`initial_prompt` 注入热词表（工部/格物/都察/Hermes/OpenClaw/小龙虾…）。
- **两段式**：快速 partial 只供 HUD 聆听屏显示；**路由与发送只用 VAD 断句后的 final 重解码**。
- partial 防跳变：local-agreement（连续 2 个 partial 一致的前缀才算"稳定"，进稳定区 container）。
- 中英混说兜底：路由词拼音模糊匹配（hé mǐ sī → Hermes，gōng bù → 工部）。
- 低置信 final（<0.6）不算失败：确认倒计时 1.5s → 3s，提示「请核对文字」。
- **资源隔离（硬条件）**：ASR 进程钉核（systemd CPUAffinity）+ CPUWeight 调高；agent 工作负载 CPUQuota 限额；突发型实例开 unlimited 模式。打断路径特殊优化：VAD 检出开口 + 轻量关键词检测即可先发 abort，不等完整转写。中期把 ASR 拆独立实例（唯一根治）。保留云端 ASR API 作降级开关。
- mic 看门狗（R2）：LISTENING 态 >800ms 无 PCM 帧 → 判定 mic 被抢（如官方 Even AI），上屏「🎤 麦克风被占用，请重说」，绝不静默空等。

### 3.2 Agent 路由器 —— 双层路由文法
- **「问X，…」= 单次借调**：本句路由给 X，徽记显示 `工→格`，回复结束自动复原。
- **「切到X」= 改粘性默认**：之后无前缀句子都走 X；待机 10 分钟粘性重置回工部。
- 「工部，…」「格物，…」「小赫，…」前缀 = 等价于借调该句（Hermes 回复同时走手机 TTS 朗读）。
- 「都察，状态」= supervisor 只读查询（健康摘要一屏）。
- 确认态 R1 滚动可切换目标 agent 并重置倒计时（ASR 把前缀听错时的零成本修正）。
- 控制词（本地热词，**不发给 agent**）：停/打住・继续・重说・等等/发・清屏・详细・读・重连・免打扰30分・开确认/关确认。
- **控制词防误触**：必须是独立短 utterance（≤4 字且前后静音 ≥300ms）+ 置信度 ≥0.85；句子中间出现不触发。

### 3.3 HUD 帧编排器（渲染协议核心）
- 输出**幂等整屏帧**：`{seq 单调递增, container分区文本, 灰阶标注}`。客户端丢弃旧序号帧；发送队列只保留最新一帧（coalescing，R3）。
- 折行器：中文标点禁则（句末标点不上行首、拉丁词不硬切，实际 16-17 字/行浮动）；**下发前强制剥离 markdown**，表格降级为「共 n 行，说『继续』在手机看」，URL 只显域名。
- 分页器：85 字/页（G2）/ 92 字/屏（G1），新页携带上页末句尾 ≤10 字暗灰锚点；**服务器端积页**：token 超速时堆成「+N 页」，每页最小驻留 4s（G1 6s）—— 由人按节奏翻页，不是屏幕追 token。
- 节流：**状态切换帧免节流**（砍掉感知延迟自伤，R9），流式正文帧 cap 2Hz（G1 1Hz）；mic 打开期间主动压到 ≤1Hz（音频上行抢带宽）。
- 自适应降频：实测帧发送耗时 > 帧间隔 → 自动减半频率并显「⌁慢」微标（唯一闭环的拥塞控制）。
- 断线重放：服务器持久化"当前帧"，重连后 1 帧恢复现场；agent run 断线期间继续跑。

### 3.4 告警管道（都察 supervisor，R11 —— 历史上发生过告警风暴）
- severity 门限：仅 critical 允许打断；同 fingerprint 去重 + 同源 5 分钟窗口合并（「磁盘告警×3」）。
- 60s 滑动窗口限流；**风暴熔断**：>10 条/分钟 → 整体降级为单条「都察告警风暴，请到手机查看」。
- 所有告警同步推手机通知 —— **HUD 不是告警唯一出口**，所以眼镜端可以保持克制。

### 3.5 WSS 可靠性（R6）
- 手机路径用**公网 WSS:443**，不用 VPN 隧道（蜂窝场景少一层 VPN 就少一类故障；VPN 仅留管理面）。
- 指数退避 + 抖动（1/2/4/…封顶 30s），单飞重连锁；按 deviceId 单会话，新连接挤掉旧连接；心跳 20s；服务器侧 5 分钟会话 TTL。

## 4. 眼镜端 UI 设计 —— 「一瞥 HUD」融合版（评审全票胜出 + 三方案精华合成）

### 4.1 设计铁律（全局验收标准）
1. **0.5 秒瞥视契约**：任何状态下，读懂状态条最左 3 字符（agent 单字徽记 + 状态符号）即知系统在干什么。层级用符号冗余编码（▸▌·⚠⧗），强日光灰阶塌缩成 2 档时依然可读。
2. **正文只放"此刻唯一值得读的那段话"**：32px 大字、17 汉字/行、5 行、85 字/页封顶；多了翻页，绝不缩字号。
3. **永不滚动、永不清屏重绘**：只整页翻进 + 整帧替换；动效只允许灰阶呼吸（L6↔L12 亮度脉动），物理上无闪烁。
4. **信息删减是默认值**：用户说一声「详细」即可换取完整展开（极简主义的官方出口）。

### 4.2 Layout

**G2（576×288，4 个 container，16 级灰阶用 4 档）**

| 区域 | 像素 | 字号 | 容量 | 内容 |
|---|---|---|---|---|
| 状态条 | y 0-31 (32px) | 24px | ≤20 字 | 最左：徽记 1 字 + 状态符 1 字；右端：计秒/倒计时 |
| 分隔线 | y=32, 1px | — | — | L3 装订线 |
| 正文 | y 32-251 (220px) | 32px，行高 44px | 17 字×5 行 = 85 字 | 稳定区 + 活跃区双 container（高频更新只触活跃区，重绘面积最小化） |
| 页脚 | y 252-287 (36px) | 24px | 1 行 | 默认全空；页码「2/3 ›」/ P3 告警。**页脚有字 = 有事可做** |

灰阶 4 档：L15 唯一焦点（当前页正文/追加句/错误词）；L10 状态条/未稳定尾段；L6 锚点/页码/提示/陈旧内容；L3 分隔线/待机点。呼吸动画专用 L6↔L12。
强光降级模式（手机光传感器触发）：压缩为 L15/L9 两档，L3 信息直接隐藏。

**G1 降级映射（640×200，5 行 × 23 字）**
- 行 1 = 微状态行（状态条+页脚合并）：`[工] ◉ 聆听 …… 0:07`，徽记带方括号补偿无灰阶。
- 行 2-5 = 正文 4 行 × 23 字 = 92 字/屏（按机型独立分页，不共用页号）。
- 无灰阶 → 全符号补偿：焦点行首「▸」、未稳定「▌」、陈旧「·」、告警「⚠」、续流缝隙「⧗」。
- 一切按 1Hz 帧预算；交互收敛到 TouchBar 长按（按上下文分派）+ 语音控制词。

### 4.3 状态机（12 态）

| 状态 | 触发 | 显示要点 | 退出 |
|---|---|---|---|
| S0 待机 | 开机/读完超时/清屏 | 近黑 + 屏中心一个 L3 灰点（点消失=链路死），0 文字 | 按键→S1；P1 告警→SA；断线→S9 |
| S1 唤醒 | 按键，下发开 mic | 状态条「工 ◉」单帧 | mic ack <300ms→S2；超时 1s→E1 |
| S2 聆听 | PCM 进入 ASR | 「工 ◉ 聆听 0:07」+ partial 大字（稳定 L15 / 尾段 L10+▌），最近 85 字窗 | VAD 800ms 静音→S3；单击=取消；G1 t≥28s→S2r |
| S2r 续流缝隙(G1) | t=28s 预重发 0x0E | 收音点「◉·」微标，基本无感；ASR 2s 重叠缓冲拼缝 | 新流 ack→S2；缝隙>500ms 且期间有语音→S3 加 ⧗ 警示 |
| S3 转写确认 | ASR final | 「→ 工部 ●●○」倒计时 1.5s（低置信 3s+「请核对文字」）+ final 全文 | 归零→发送→S4；「重说」回 S2；「等等」暂停；R1 滚动换 agent |
| S4 思考中 | runId 返回，无 delta | 「工 ◔ 思考 6s」呼吸点 1Hz + 问题首行回显 L6 | 首 delta→S6；tool 事件→S5；>30s→E7 慢响应子态；「停」→abort |
| S5 工具执行 | tool 事件 | 「工 ⚙ 工具 14s」+ 工具中文名（白名单映射）+ 摘要参数 ≤12 字（只白名单搜索词/文件名） | 工具结束→S4/S6 |
| S6 流式回复 | delta 持续到达 | 「工 ▸ 回答」+ 句边界成块填充，满 85 字整页翻进带锚点，页脚「‹n」 | final 且≤85 字→显示 15s 渐隐；>85 字→S7；「停」→已收文本保留进 S7 |
| S7 翻页阅读 | final 多页 / 流中回翻 | 「工 ✓ 完成」+ 页码「2/3 ›」；「读」=手机 TTS | 末页 10s 无操作→S0 |
| S8 错误 | E1-E8 | ≤2 行：错误词 ≤8 字 + 动作提示 ≤10 字。不显示错误码 | 自动恢复成功→原状态；重试耗尽→静态等按键 |
| S9 断线重连 | 心跳丢 2 次 | 「⟲ 重连 n」+ 断前内容压暗 L6 | 退避 5 次失败→「服务器失联·长按重试」 |
| SA 都察告警 | supervisor 事件 | P3 只占页脚 ≤20 字 10s；P2 状态条横幅 3s×2 后退页脚驻留；P1 全屏接管但**绝不抢活跃流式**（先 P2 预告，final 后接管） | 确认/超时 |

### 4.4 信息预算 —— "坚决不显示"清单
时间戳/日期、runId/任何 ID、token 计数与费用、模型名、服务器地址/延迟毫秒数、工具原始 JSON、thinking 内容、进度条/spinner 图片、logo/寒暄、电量（仅 <15% 页脚出现一次「⚡15%」）、agent 在线列表、同屏第二条正文。

### 4.5 更新节奏

| 状态 | G2 | G1 | 策略 |
|---|---|---|---|
| 待机/阅读 | 0 Hz | 0 Hz | 静态 |
| 聆听 | ≤2 Hz | 1 Hz | 只重绘活跃区 container；稳定前缀 append-only |
| 思考 | 1 Hz | 0.5 Hz | 计秒+呼吸同帧 |
| 工具 | 事件驱动 + 0.5Hz 计秒 | 同 | 单帧 |
| 流式 | cap 2 Hz | cap 1 Hz | 混合 flush：句边界立即（距上帧<400ms 则合并）/ 1.2s 定时且缓冲≥4 字 / ≥34 字强制 / 满页翻进 |
| 状态切换帧 | **免节流** | 免节流 | 感知延迟优先 |

防闪烁四规则：整帧替换不清屏；只翻页不滚动（滚动需 >5Hz，超 BLE 预算）；分 container 独立更新；元素最短驻留 500ms。

### 4.6 mic 策略（分路径）
- **G2**：思考/工具/流式期间 mic 常开，但只跑控制词热词检测（不转写正文）—— 眼镜无扬声器 = 无回声，「停」即时生效零成本。
- **G1**：非聆听态关麦（30s 上限 + 续流成本），打断靠按键。
- 通用：聆听态显著 ●REC + 剩余秒数倒计时；单段发言软上限 20-25s，从设计上不触碰 30s 红线。

### 4.7 失败态恢复政策
- **幂等性分流**：只读查询类自动重试 1 次（带倒计时标注）；**有写操作/工具副作用的绝不自动重试**，只提示手动。
- 重连后**绝不自动重发**未送达话语：「已重连 · 单击重发」（防幽灵发送）；错误态保留用户原话在屏。
- E4 agent 错误：「✕ 出错」+ 摘要 ≤17 字 + 「说『重说』或『换格物』」；同问题连错 2 次自动建议切格物（仅建议）。
- E5 G1 右镜腿 ack 超时：左屏照常 + 状态条「右镜失联」，恢复后整帧对齐右屏。
- E8 插件被杀后台重生：重建 container 后网关下发"最后 HUD 帧"快照恢复现场（>10 分钟则回待机）。
- 错误文案同 32px 字号，不缩小、不闪。

## 5. 延迟预算（说完话 → 看到第一个回答字）

| 跳 | 典型 | 备注 |
|---|---|---|
| 眼镜 mic→BLE→手机 | 50-150ms | |
| 手机→WSS 上行(4G) | 50-150ms | |
| VAD 判停 | 300-500ms | |
| ASR final 重解码 | 400-800ms | CPU 积分悬崖时 2-3s（必须 unlimited+钉核） |
| 路由 + chat.send | ~50ms | |
| **agent 首 token** | **2000-4000ms** | 最痛一跳，网关层不可压缩 |
| HUD 帧编排 | ~0ms | 状态帧免节流后 |
| WSS 下行 + BLE 渲染 | 250-650ms | |
| **合计** | **3.1-7.2s**（长尾 10s+） | |

工程重心放在**感知延迟**：VAD 判停后 ≤300ms 必须上「✓ → 工部思考中」帧；思考屏显示已等秒数；ASR final 一出就并行发 chat.send 与确认帧。

## 7. 落地路线图
