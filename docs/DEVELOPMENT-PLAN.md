# EvenRealities-Claw 开发计划

> v0.1 · 2026-06-11
> 目标：通过 Even Realities G2 智能眼镜，以语音随时调用私有服务器上的 OpenClaw 多 Agent 系统（工部 / 格物 / 都察）与 Hermes Agent，并在眼镜 HUD 上获得实时状态反馈与回复。
> 系统设计依据见 [DESIGN.md](./DESIGN.md)（含完整调研引用、HUD 状态机、红队风险清单 R1-R14）。

---

## 0. 已确认的产品决策

| 决策点 | 结论 | 影响 |
|---|---|---|
| 硬件 | G2（已有/已订购） | 主路径 = Even Hub 官方插件；眼镜到手前用官方模拟器开发 |
| 产品形态 | 接受亮屏使用 | 定位"掏出手机亮屏 → 按住说话 → 看眼镜 → 收起"的突发会话助手；锁屏存活只作实测项，不作承诺 |
| MVP 边界 | 纯 HUD 文本 | 说话→看字闭环；TTS 语音朗读推迟到阶段三 |
| 唤醒方式 | 按住说话（push-to-talk） | 无唤醒词、无 always-on 监听（隐私 + 平台约束双重原因，见 R12） |

## 1. MVP 定义（= 阶段二完成时的产物）

**一句话**：手机亮屏打开 Even App 里的插件，按住说话对工部提问，眼镜 HUD 上实时看到「转写 → 思考/工具状态 → 分页回复」。

**包含**：
- 单 Agent（工部），按住说话，无唤醒词
- HUD 实时转写（partial 上屏）、状态条（聆听/思考/工具/回答 + 计秒）
- 回复按 85 字/页分页显示，按键/语音翻页
- 完整失败态：断线重连恢复现场、mic 被抢检测、错误提示
- 设备配对 + 短时效 JWT 安全体系

**不包含**：TTS 朗读、多 Agent 路由、都察告警、锁屏可用。

**验收标准（户外 4G 真实场景）**：
1. 松开按键后 **< 1s** 转写出现在 HUD；
2. **< 5s** 看到首个回复帧（含"思考中"状态帧填充等待期）；
3. 断线后重连，**1 帧**恢复现场（回复在断线期间继续生成，回来直接看结果）;
4. OpenClaw 网关凭证 **零出服务器**（手机端只持有设备 JWT）；
5. 原始音频 PCM 不落盘。

## 2. 阶段一 · 地基与模拟器闭环（预估 2-3 周）

> 原则：眼镜未到手也能全速推进——除真机实测外的一切都在本阶段完成可测版本。

| # | 任务 | 做什么 | 为什么 / 验收 |
|---|---|---|---|
| 1.1 | Monorepo 工程化 | `plugin/`（TS，Even Hub 插件）、`gateway/`（Python，Lens Gateway）、`protocol/`（JSON Schema 单一事实源）、`docs/`；lint/format/test 脚手架 | 双语言项目必须从协议出发组织。验收：CI 本地脚本一键跑通 lint+test |
| 1.2 | HUD 帧协议定稿 | 定义幂等整屏帧：`{seq 单调递增, containers: {status, body_stable, body_active, foot}, 灰阶标注}`；上行消息：`{audio_chunk, ptt_start/stop, page_turn, abort}`；JSON Schema → TS 类型 + Python 模型双端生成 | 协议是插件与网关的契约，先冻结再开发。验收：双端类型由同一 Schema 生成，回环测试通过 |
| 1.3 | 插件骨架 | 基于官方 `asr` 模板起步；evenhub-cli + 官方模拟器跑通：建 4 个文本 container、渲染服务器下发的假帧、采集 PCM 转发 WSS | 验证官方工具链 + 渲染通路。验收：模拟器中看到假帧按 2Hz 刷新且无闪烁 |
| 1.4 | Lens Gateway 骨架 | WSS 服务（asyncio）；设备配对流程：配对码 → 发设备绑定 15min JWT + refresh token，可吊销；echo 回环模式 | 安全体系（R8）必须从第一天就在。验收：未认证连接被拒；JWT 过期自动刷新；echo 往返 < 100ms |
| 1.5 | OpenClaw 适配器 | loopback WS 连工部网关：connect 握手、`chat.send` → delta/final/error 事件流、`chat.abort`、runId 僵尸标记防竞态（R14）；lens 专属 sessionKey（`lens:<agent>:<deviceId>`）+ 小屏输出风格 system 段注入 | 这部分完全不需要眼镜，可带单测完整交付。验收：CLI 工具发问题 → 流式收到工部回复事件；abort 后迟到事件被正确丢弃 |
| 1.6 | ASR 离线管线 | faster-whisper small/int8：systemd CPUAffinity 钉 2 核与 agent 负载隔离（R4/R5）、实例开 unlimited 模式、热词 initial_prompt（工部/格物/都察/Hermes/OpenClaw）、local-agreement 防 partial 跳变、VAD 端点检测；用录音文件回放做基准测试 | ASR 是延迟与准确率的最大自变量，先离线调优。验收：录音回放 RTF < 0.6，partial 间隔 ≤ 800ms，路由热词识别率实测记录在案 |
| 1.7 | 状态机整合（模拟器闭环） | 帧编排器实现 S0-S9 全状态机：折行（中文标点禁则）、85 字分页 + 锚点、混合 flush（句边界/1.2s 定时/满页）、状态切换帧免节流、正文帧 cap 2Hz | 阶段一的总验收。验收：**模拟器中完整走一遍**——键盘模拟按住说话、音频文件灌入、真工部回复逐页上模拟屏，全程无闪烁无乱序 |

**风险与依赖**：Even Hub SDK 仍是 v0.0.x，API 可能变动（R13）→ 插件层做薄、协议适配层隔离;官方模拟器与真机行为可能有差异 → 阶段二 2.1 实测校准。

## 3. 阶段二 · 真机最小闭环 = MVP（预估 2-3 周，眼镜到手后启动）

| # | 任务 | 做什么 | 为什么 / 验收 |
|---|---|---|---|
| 2.1 | 五项真机实测 | ① 插件后台/锁屏存活时长（iOS/Android 分别测）；② 官方 Even AI 抢 mic 四象限实测；③ TouchBar 事件对插件的暴露程度；④ `audioControl` 连续开启 60s/300s 行为；⑤ 真实可达刷新率（依手机机型） | 这五个数字是调研无法回答的未知数（R1/R2），决定状态机最终参数。验收：产出《实测约束表》并据此校准 1.7 的参数 |
| 2.2 | 真机音频通路 | mic PCM → WSS → ASR 全链路；PCM 帧到达率看门狗：聆听态 > 800ms 无帧判定 mic 被抢，上屏「麦克风被占用」而非静默空等 | 消灭"无声失败"（R2 最危险形态）。验收：录音中长按 TouchBar 触发 Even AI，HUD 在 1s 内给出明确提示 |
| 2.3 | HUD 真机渲染 | 1.7 的状态机上真机：实测字号/行宽微调（17 字/行 × 5 行基线）、灰阶 4 档层级、防闪烁四规则验证 | 模拟器≠真机光学。验收：步行中 0.5s 瞥视可读懂状态条；流式回复无闪烁感 |
| 2.4 | 公网部署 | caddy 443 TLS 反代 + 速率限制 + fail2ban；WSS 断连协议：指数退避+抖动、deviceId 单会话（新连接挤掉旧的）、心跳 20s、服务器持久化当前帧、重连重放 | 蜂窝网络断连是常态而非异常（R6）。验收：手机飞行模式 30s 再恢复，1 帧回到现场 |
| 2.5 | 插件本地看门狗 | 心跳超时 2 次 → 插件用本地模板向眼镜推「连接丢失」帧 | 哑终端唯一必须自带的逻辑：消灭"旧帧撒谎"（R1 衍生故障）。验收：拔网线后眼镜 ≤ 60s 显示断线帧 |
| 2.6 | MVP 端到端验收 | 按 §1 验收标准在户外 4G 场景实测并记录数据 | MVP 发布门槛 |

**风险与依赖**：依赖眼镜到货；若 2.1 实测发现 TouchBar 事件不暴露给插件 → 交互退化到 R1 戒指 + 语音控制词（设计已预留）；若 audioControl 存在隐藏时长上限 → 按住说话软上限相应下调。

## 4. 阶段三 · 多 Agent + 告警 + 语音（预估 2 周）

| # | 任务 | 做什么 | 为什么 / 验收 |
|---|---|---|---|
| 3.1 | 双层路由文法 | 「问格物，…」= 单次借调（徽记显 `工→格`，回复完自动复原）；「切到格物」= 改粘性默认（10 分钟待机重置）；拼音模糊匹配兜底（hé mǐ sī → Hermes）；路由只认 VAD 断句后的 final 重解码 | 单次问询 ≠ 切换默认，混淆会造成"问错人"。验收：中英混说路由词识别率实测 ≥ 95% |
| 3.2 | 格物 / 都察接入 | 每 Agent 独立 `lens:<agent>:<deviceId>` 会话 + 小屏风格 system 段；「都察，状态」只读健康查询一屏 | 会话隔离防止互相污染（R7）。验收：三个 Agent 互切上下文不串 |
| 3.3 | Hermes + TTS 朗读 | Hermes 通路接入；「读」控制词 = 手机 TTS 朗读当前页；对小赫（Hermes）的提问回复自动朗读 | 骑车等不便看 HUD 的场景出口。验收：「读」从发声到出声 < 2s |
| 3.4 | 都察告警管道 | severity 门限（仅 critical 可打断）、指纹去重、同源 5 分钟合并（「磁盘告警×3」）、风暴熔断（>10 条/分钟 → 单条降级提示）、P1-P3 三级插入（P3 只占页脚 / P1 绝不抢活跃流式） | 监工告警有刷屏前科（R11），必须先建堤坝再开闸。验收：模拟告警风暴，HUD 始终只显示折叠摘要 |
| 3.5 | 控制词全集 + 防误触 | 停/继续/重说/等等/清屏/详细/读/重连/免打扰30分/开关确认；防误触：独立短 utterance（≤4 字 + 前后静音 ≥300ms）+ 置信度 ≥0.85；G2 在思考/流式期间 mic 常开只跑热词检测（「停」即时生效） | 控制词出现在正文里不能误触发。验收：朗读一段含"停""继续"的正文，零误触 |
| 3.6 | 跨通道续聊 | 「详细」= 自动追问展开；「接上 Discord 话题」= 网关摘要 Discord 会话后注入 lens 会话 | 隔离会话的可用性补偿。验收：续聊后 Agent 能正确引用 Discord 上下文要点 |

**风险与依赖**：TTS 经手机扬声器在户外可用性未知 → 优先支持蓝牙耳机；告警管道依赖都察事件格式稳定。

## 5. 阶段四 · 健壮化与战略备份（按需推进）

| # | 任务 | 做什么 | 为什么 / 验收 |
|---|---|---|---|
| 4.1 | 锁屏/后台攻坚 | 基于 2.1 实测数据：各 ROM 保活配置文档、重连快照打磨、必要时引导用户加保活白名单 | 把"惊喜"尽量变成"功能"，但不承诺（R1 平台不可控） |
| 4.2 | G1 BLE 备份路径 | 渲染器适配层：同一 Lens Gateway 与帧协议，G1 渲染器（5 行 × 23 字、1Hz、双链路串行、符号替代灰阶）；树莓派/常电安卓做 BLE 中继 | 官方平台变故时 48h 可切换（R13）；同时覆盖"家中常驻"场景。验收：同一对话在 G1 中继上完整走通 |
| 4.3 | 自适应降频 + 强光降级 | 实测帧发送耗时 > 帧间隔 → 自动减半频率显「⌁慢」；手机光传感器触发灰阶压缩两档 | 真实世界的带宽与光照都不按基线来（R3）。验收：人为限速后系统自动降频不崩溃 |
| 4.4 | 运维与扩容评估 | lens-gateway 接入都察监控体系（health 探针）；评估 ASR 拆独立实例（R5 唯一根治方案）；凭证轮换流程文档化 | 长期运行的卫生条件。验收：都察能监控 lens-gateway 并按 3.4 管道告警 |

## 6. 里程碑总览

```
阶段一 (2-3周)        阶段二 (2-3周)        阶段三 (2周)         阶段四 (按需)
模拟器闭环      →     真机 MVP        →    多Agent+告警+TTS  →  健壮化+G1备份
  无需眼镜              眼镜到手后              │                    │
  1.1-1.7              2.1-2.6 ★MVP发布       3.1-3.6              4.1-4.4
```

**关键路径**：1.2 协议定稿 → 1.7 模拟器闭环 → 2.1 实测约束表 → 2.6 MVP。
**并行机会**：1.5 OpenClaw 适配器与 1.6 ASR 管线完全独立，可并行;阶段二等待眼镜到货期间可预研 3.1 路由文法。

## 7. 不在本计划范围内

- 图片/图表上屏（官方明确不鼓励频繁发图，且文本已满足状态反馈需求）
- always-on 唤醒词监听（隐私 + 平台 + 功耗三重否决）
- 眼镜端独立运行（无论 G1/G2 都必须有 host 中继，物理约束）
- 多用户/多设备并发（个人系统，单用户单眼镜）
